# 质量门禁

在动作复核、蒙版处理和最终 Bundle 验证阶段应用这些门禁。任何门禁无法判断时，明确标注不确定性并请求用户复核，不要自行降低标准。

## 动作分段门禁

- 分页查看全部动作，确认最后一页 `hasMore: false`。
- 对照八帧概览检查主体动作是否从一种语义状态切换为另一种；不要只依据画面闪烁、特效变化或背景变化命名动作。
- 检查相邻段是否属于同一连续动作。硬切附近若只改变特效或镜头而主体连续，标记为疑似误切。
- 检查一个动作段内是否出现两个以上明显不同动作。出现时标记为疑似漏切，并走回退流程。

## 循环候选门禁

- 主体动作必须完整：起势、主要运动和回到可重复姿态都应包含。
- 接缝前后三帧的主体位置、轮廓、速度方向和运动幅度应连续。
- 优先选择最早完整循环，而不是得分更高但只覆盖特效微循环的短候选。
- 若末帧与首帧重复，令 `export_end_exclusive` 排除重复末帧；避免播放时产生停顿。
- 记录每个选择的理由和置信度。低置信度时展示候选差异，不要静默决定。

## 动作导出门禁

- 多动作计划必须覆盖所有已接受动作，名称必须唯一且适合作为文件名或引擎动画名。
- `export_start_frame` 和 `export_end_exclusive` 必须位于对应动作段内。
- 执行后所有必需项必须为 `exported`；任何 `failed` 都阻止 Bundle 阶段。
- `skipped` 只有在用户明确接受缺失动作时才允许继续。
- 默认不得覆盖既有目录；改用新目录或取得明确的 `replace` 授权。

## 蒙版门禁

- 将 `suspiciousDetachedComponents` 和 `suspiciousHoles` 逐帧映射回复核图，区分真实缺陷与合理细节。
- 不要仅因存在 `partiallyTransparentPixels` 判定失败；正常抗锯齿、运动模糊和发光边缘可能需要半透明。
- 修复背景残点时使用 `remove`；恢复主体孔洞时必须提供原始源帧并使用 `restore`。
- 精修后重新诊断。可疑区域未清零时，必须逐项确认其合理性或披露剩余风险。
- 不要使用大面积自动清理替代视觉判断；自动清理阈值必须小于明确要移除的缺陷区域。

## Bundle 门禁

- `validate_sprite_bundle.valid` 必须为 `true`。
- `errors` 必须为空；否则修复后重新导出和验证。
- `duplicateEndpoint: true` 通常表示重复闭环帧。返回动作边界阶段，排除重复末帧后重新生成。
- 检查每个动作的 `seamDifference`、`seamAlphaDifference` 和 `meanAlphaFlicker`。这些指标没有通用绝对阈值；结合复核图、动作类型和同一 Bundle 内其他动作判断。
- Alpha 接缝或闪烁明显高于同组其他动作时，重新抠图或精修，不要仅忽略警告。
- 非 Generic 预设必须存在对应的 Aseprite、Godot 或 Unity 配套文件，且动画和帧数量一致。

## 完成门禁

同时满足以下条件才可宣称完成：

1. 所有目标动作均已复核并成功导出。
2. 透明背景需求已完成二次蒙版诊断，或用户明确接受剩余风险。
3. Atlas、Manifest 和所需配套文件均存在。
4. 最终 Bundle 验证为 `valid: true`。
5. 最终报告披露分析 FPS、重采样、低置信度选择和所有警告。
