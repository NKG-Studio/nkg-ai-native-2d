# 失败回退

只在对应异常出现时读取并应用本文件。优先保留原始输出和报告，不要用覆盖操作隐藏失败。

## FrameLoop MCP 不可用

1. 确认项目依赖已安装，并构建 `@frameloop/mcp`。
2. 使用仓库提供的 `.codex/config.toml.example` 或 `codex mcp add` 注册本地服务。
3. 重启 Codex 后确认 `frameloop` 工具可见。
4. MCP 恢复前停止工作；不要用未经用户要求的临时脚本替代完整流程。

## 报告或计划失效

分析报告和导出计划保存在临时目录，不能视为长期资产。

- `report_id` 无法读取时，使用相同视频、FPS 和循环参数重新执行分析与复核。
- `plan_id` 无法读取时，从已保存的动作复核表重新创建计划。
- 不要根据记忆猜测 UUID、帧边界或输出目录。

## 未检测到动作或候选

1. 确认视频可解码、时长和 FPS 正常。
2. 对快速动作提高分析 FPS；对长周期动作提高 `max_loop_seconds` 和分析窗口。
3. 对短循环降低 `min_loop_seconds`，但不要低到只捕获闪烁或局部特效。
4. 重新分析后仍无可靠候选时，说明输入可能不是稳定循环，不要强行生成“循环”图集。
5. 用户能提供明确时间区间时，改用 `export_loop_frames` 导出人工区间，并在交付中标记为手工边界。

## 多动作漏分段

平滑转场、无硬切的连续动作或低对比变化可能被合并为一段。

1. 使用 `read_analysis_report` 检查窗口、场景切分和候选在时间轴上的分布。
2. 提高分析 FPS 或缩短分析窗口后重新分析，验证是否获得更清晰的局部变化。
3. 若仍被合并，停止自动批量计划。
4. 请求用户给出大致时间点，或由多模态复核确定明确区间；逐段调用 `export_loop_frames` 输出到独立目录。
5. 将这些目录作为多个动画传入 `export_sprite_bundle`，并明确记录手工分段。

## 同一动作被误切成多段

快速闪光、特效或镜头震动可能产生伪硬切。

1. 对照相邻动作概览确认主体是否连续。
2. 不要把伪切段分别命名并导出。
3. 当前批量计划无法合并报告中的动作段时，改用包含完整动作的人工时间区间和 `export_loop_frames`。
4. 重新检查首尾接缝，并记录合并区间的依据。

## 候选之间无法判断

- 增加 `candidates_per_action`，查看同一动作的更多候选。
- 使用 `read_analysis_report` 比较分数构成，但不要让数值取代语义判断。
- 并列候选中优先选择最早完整周期；若接缝质量明显不同，再选择更平滑者。
- 仍无法判断时，向用户展示候选帧范围和差异，请求选择。

## VFR 或原始帧保真要求

当前视频分析与导出按指定 FPS 重采样，可能丢弃或重复源帧。

- 若用户只需要稳定播放的 Sprite 动画，继续并披露分析/导出 FPS。
- 若用户要求严格保留每个源帧或原始 PTS，停止并说明当前 MCP 尚不满足；不要把重采样输出描述为原始帧。

## 抠图失败

- 纯色背景结果不稳定时，检查键色、容差和边缘去色溢出参数后重试。
- 复杂背景优先使用 AI 蒙版；模型不可用或质量不足时保留原背景，并征求用户是否接受。
- 孔洞、离散背景残点或局部边缘问题使用 `refine_matte_batch` 小范围修复。
- 大面积主体缺失时重新抠图，不要用大笔刷逐帧伪造主体。

## 输出冲突或批量导出失败

- 默认保留 `fail`；选择新的输出根目录最安全。
- 只有用户明确要求覆盖时才重新创建 `replace` 计划。
- 修复单项失败后重新创建计划，避免复用状态不明的旧计划。
- 保留成功项的 Manifest；不要在未核对时删除已导出的用户文件。

## Bundle 验证失败

- 尺寸、坐标或帧数错误：重新收集帧路径并重新导出 Bundle。
- 缺少引擎配套文件：使用同一预设重新导出，不要手写不完整文件。
- 重复末帧警告：返回动作导出阶段，减小 `export_end_exclusive` 后重建。
- Alpha 闪烁或接缝异常：重新诊断/精修蒙版，再重建并复验。
- 每次修复后重新调用 `validate_sprite_bundle`；不要沿用旧验证结论。
